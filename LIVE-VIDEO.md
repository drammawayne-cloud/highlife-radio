# Radio and live picture

The homepage uses an HTML audio element as the audible programme master, with a separate always-muted picture element reading the same combined HLS programme. This keeps sound eligible for background playback when a phone suspends video. There is no autoplay. Play/Pause controls both, and full screen changes only the picture size. The native app uses one background-enabled Expo Video player for its combined programme. No Web Audio graph processes listener sound.

While the page is hidden, only its muted picture is paused and released. The audio master continues. On return, the picture reconnects and aligns to the audio programme date/time; it stays covered by the station poster until aligned. Video corrections never seek or pause the audible master. Media Session provides system Play/Pause and metadata, and supported browsers use the playback audio session. Calls, recording, other media, browser termination, and network loss can still interrupt listening under the phone operating system.

The server service in `ops/program-feed` receives the existing OBS source privately. AzuraCast's public programme MP3 is the only audio input to its output encoder. It includes the centrally inserted commercials and the subsequent return to programming. OBS audio is used only to identify the corresponding picture time and is never mixed into the output sound.

The service compares eight seconds of 25 ms audio energy measurements in a bounded RAM history. Two consistent, unique matches establish the correspondence between the radio audio clock and OBS timestamps. The encoder chooses the corresponding buffered picture for every output video frame. Its H.264 picture and AAC station audio are then multiplexed together. If OBS is absent or a content match is uncertain, it sends a black picture while continuing station audio; the website displays its logo and the current New York rotation over that area. No live recordings are written.

The service runs as `highlife-program.service`, with automatic restart, a 900 MB memory limit, a two-core CPU limit and a read-only filesystem apart from its private runtime status directory. Its OBS endpoint is read from the existing protected server configuration. Publisher credentials do not appear in the repository, browser, logs or public URLs. Only the source of the existing public MediaMTX `highlife-radio` path changed, to a loopback MPEG-TS feed. Other station configurations and OBS/Serato playback are preserved.

The fixed `/radio-program/` proxy serves the existing public picture feed through the website's regular HTTPS connection. It permits only GET/HEAD for HLS asset filenames, forwards only the HLS session parameters, and rejects redirects to another host. It does not forward the listener's browser cookies. If the programme feed is unavailable, the player automatically falls back to the original station MP3 for a minute. The fallback retains the hourly commercials.

The radio reconnects after network errors or prolonged buffering with a capped retry delay. A fresh connection avoids reusing an expired stream response. User Pause cancels retries and any pending programme start. iPhones retain the native media playback path rather than routing sound through Web Audio. The waveform uses a separate public amplitude feed from the encoded station programme. It does not route or change listener audio. The same display works on phones without a Web Audio graph.

Double-tap/double-click expands the station picture; repeat returns. Enter/Space and Escape are keyboard alternatives. Native full screen is preferred, with a full-window fallback. No gesture instructions cover the picture. The station logo and daily rotation appear when paused or when a live picture is unavailable.

## Rollback

Remove `programUrl` from `station.json` to retain audio playback with the original MP3 and logo. To restore the previous raw picture source, restore the private server backup `/etc/richrow-video/mediamtx.before-combined-program.yml` and stop `highlife-program.service`. Neither rollback needs to stop OBS, Icecast, Liquidsoap or Serato. Do not print the private MediaMTX configuration: it contains existing publisher information.

## Audio-reactive waveform

`highlife-waveform-meter.service` reads completed HLS segments into RAM and extracts amplitude samples with their programme date/time. It writes only bounded numerical levels to the station volume. An exact Nginx location publishes that JSON; the website proxies it through `/api/radio-waveform`. The meter restores its single public route after container replacement, without exposing any other station files. Its service is enabled with automatic restart and memory/CPU limits. No media recordings are retained.

Both waveform displays select level history at the listener's HLS playback date/time. Native phone playback uses its programme start date where available, with a buffered-position estimate as a fallback. The display resets on pause and discards stale measurements. Reduced-motion mode uses a slower functional meter update. No microphone, AudioContext or additional audible stream is opened.

Validation: live segment amplitude levels varied from quiet to loud; two browser observations showed different non-flat bar heights during playback; Pause returned all bars to 3 pixels. Fourteen web tests passed, including playback-time selection and missing/silent/stale level handling. A physical phone listening check remains user-provided rather than automated.
